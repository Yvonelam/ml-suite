GETTING STARTED
快速开始
步骤 1
开通服务

选择 MCP 套餐，或确保当前账号有可用积分。

步骤 2
创建 API Key

创建后立即安全保存完整 Key，关闭弹窗后无法再次查看。

步骤 3
填写客户端配置

配置服务地址，并通过 X-API-Key 请求头发送 Key。

步骤 4
验证连接

重新加载客户端，调用 get_my_quota_status 检查额度。

账号与密钥说明
同一当前账号下的 API Key 共用该账号的 MCP 套餐额度；完整 Key 丢失后只能删除并重新创建。
CLIENT SETUP
客户端配置

选择客户端并复制配置，将示例中的 sk-替换为你的APIKey 替换为创建时保存的完整密钥。

通用 JSON
Codex
Claude Desktop
Cursor

适用于支持自定义请求头的远程 MCP（Streamable HTTP）客户端。

通用 JSON 配置
复制内容
{
  "type": "http",
  "url": "https://mcp.damaishuju.com/tools/mcp",
  "headers": {
    "X-API-Key": "sk-替换为你的APIKey"
  }
}

命令行联调可将 API Key 保存到环境变量 DM_MCP_API_KEY 后使用以下 cURL。response_format=json 便于脚本解析工具结果。

cURL 联调示例
复制内容
curl -sS -X POST \
  "https://mcp.damaishuju.com/tools/mcp?response_format=json" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "X-API-Key: ${DM_MCP_API_KEY}" \
  -d '{
    "jsonrpc": "2.0",
    "id": "1",
    "method": "tools/call",
    "params": {
      "name": "search_product_snapshots",
      "arguments": {
        "market_code": "MLM",
        "sku_id": "MLM1602785195",
        "limit": 1
      }
    }
  }'
响应解析
先检查 HTTP 状态码、JSON-RPC error 和 result.isError；成功业务数据通常位于 result.content[].text，text 还需要再次解析为 JSON，部分客户端会同时返回 structuredContent。
API Key 安全提示
请妥善保管完整 API Key，密钥丢失后只能删除并重新创建。

工具 1
类目搜索search_categories
免费

通过类目关键词查找候选类目，适合在商品搜索前获取 category_id。

使用说明
query 为类目关键词，仅支持所选市场当地语言；market_code 默认 MLM；limit 默认 100、最大 100。
请求参数
字段	类型	必填	说明
market_code	string	否	市场编码，默认 MLM。
query	string	否	类目关键词。
limit	integer	否	返回数量，默认及最大 100。
返回内容
字段	类型	说明
request_overview	object	包含 market、search_text 和 page_size 等请求摘要字段。
record_count	integer	本次返回类目数。
records	array	类目列表；记录包含类目 ID、名称、层级、路径、叶子类目标识、近 30 天销量与 GMV、均价、商家数和活跃商品数。
records[].taxonomy_code	string	类目 ID。
records[].taxonomy_name	string	类目名称。
records[].taxonomy_trail	array	类目路径。
records[].taxonomy_trail_localized	array	本地化类目路径。
records[].taxonomy_trail_english	array	英文类目路径。
records[].taxonomy_name_localized	string	本地化类目名称。
records[].taxonomy_depth	integer	类目层级。
records[].is_terminal_taxonomy	boolean	是否为叶子类目。
records[].orders_last_30_days	integer	近 30 天销量。
records[].revenue_last_30_days	number	近 30 天 GMV。
records[].average_selling_price	number	平均售价。
records[].merchant_count	integer	商家数。
records[].active_listings_last_30_days	integer	近 30 天活跃商品数。
请求示例
JSON 请求示例

  "limit": 10

返回示例

工具 3
商品搜索及属性聚合search_product_snapshots
扣减次数

按关键词、类目、商品、店铺、价格、销量、评分、评论和上架时间等条件筛选 Mercado Libre 商品；关键词仅支持所选市场当地语言。

使用说明
至少提供 keyword、category_id、sku_id、shop_id、shop_query、product_url 之一。
请求参数

shop_query	string	条件必填	店铺名或卖家名关键词。

工具 4
商品销量趋势product_sales_trend
扣减次数

读取商品日销量历史并聚合为月销量和周销量，最长查询约两年数据。

使用说明
sku_id 必填；market_code 默认 MLM；days 默认 730、最大 731。
请求参数
字段	类型	必填	说明
sku_id	string	是	商品 ID。
market_code	string	否	市场编码，默认 MLM。
days	integer	否	查询天数，默认 730，范围 1 至 731。
返回内容
字段	类型	说明
market_code	string	市场编码。
product_code	string	商品 ID。
range_start_date	string	实际查询开始日期。

requested_day_count	integer	请求查询天数。
covered_day_count	integer	实际覆盖天数。
data_available	boolean	是否有销量数据。
data_coverage	object	数据覆盖情况。
aggregation_period	object	月、周聚合模式和日期时区模式。
monthly_order_series	array	月销量序列。
weekly_order_series	array	周销量序列。
notices	array	数据不足或覆盖提示。
input_method	string	数据输入方式。
data_coverage.requested_day_count	integer	覆盖统计请求天数。
data_coverage.covered_day_count	integer	覆盖统计实际天数。
data_coverage.full_coverage	boolean	是否完整覆盖。
data_coverage.coverage_start_date	string	覆盖开始日期。
data_coverage.coverage_end_date	string	覆盖结束日期。
aggregation_period.month_mode	string	月聚合模式。
aggregation_period.week_mode	string	周聚合模式。
aggregation_period.timezone_mode	string	日期时区模式。
monthly_order_series[].month	string	月序列月份。
monthly_order_series[].orders	integer/number	月序列销量。
weekly_order_series[].week	string	周序列 ISO 周。
weekly_order_series[].orders	integer/number	周序列销量。
